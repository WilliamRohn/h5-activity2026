# 9:16 矩形拼图与 20,000 块性能报告

## 测试目标

本报告验证 `100 × 200 = 20,000` 块拼图在一次性恢复 19,200 个已点亮坐标后的初始化、单块状态切换和缩放表现，并对比以下两种渲染链路：

- 基线：`628 × 1099 SVG → 900 × 1600 Canvas → CSS transform`。
- 优化：`SVG → 视口尺寸 × DPR Canvas`，缩放和平移进入 Canvas 绘制矩阵。

测试素材为 `public/images/jiaoxuelou.svg`。画布严格使用 `9:16`，源图按高度居中裁切；目标源区域宽度约为 `618.19`，即 SVG 左右各裁约 `4.91` 个坐标单位，不拉伸图像。

## 数据与实现

Mock 接口固定延迟 200ms，返回结构为：

```js
{
  columns: 100,
  rows: 200,
  litPieces: [{ x, y }],
}
```

`mockSeed: 20260804` 使每次运行获得同一组 19,200 个合法且不重复的零基坐标。前端 hydration 一次性写入 `Uint8Array` 状态表和剩余领取池，只触发一次 React 状态更新；初始化后进度为 `19,200 / 20,000`，随机领取池剩余 800 块。

优化版仅保留一个可见 Canvas。`100 × 200` 的逻辑蒙版负责状态合成，彩色层、置灰层和合成层放在离屏 Canvas；单块切换只修改一个蒙版像素并刷新相应脏矩形。可见 Canvas 的 DPR 上限为 3，网格线在物理像素上对齐。

## 测试环境与方法

- 生产构建通过 Vite 本地预览运行。
- 浏览器：Codex 应用内 Chromium。
- 主要数据视口：`375 × 812`，DPR 2。
- 初始化数据：固定种子的 19,200 个坐标。
- 初始化测试：基线和优化版各运行 3 次，报告中位数与样本 P95。
- 单块切换：在同一块上交替点亮/取消 10 次。
- 缩放：优化版从 100% 通过按钮放大至 500%，记录 8 次视口重绘。
- 性能采集仅在 `?perf=1` 下启用；`?perf=1&renderer=baseline` 进入基线实现。

P95 采用本轮有限样本的最近秩结果，主要用于发现数量级差异，不等同于大样本实验室基准。

## 初始化结果

| 指标 | 基线中位数 | 基线 P95 | 优化中位数 | 优化 P95 |
| --- | ---: | ---: | ---: | ---: |
| Mock 请求总时间（含 200ms 延迟） | 216.6ms | 218.6ms | 209.1ms | 211.4ms |
| 坐标生成、序列化与解析 | 4.0ms | 4.5ms | 4.2ms | 4.5ms |
| hydration | 0.9ms | 1.1ms | 1.3ms | 1.4ms |
| hydration 至首个 Canvas 完成 | 3,082.3ms | 3,089.7ms | 3.3ms | 3.5ms |
| 19,200 块状态绘制/合成 | 3,081.3ms | 3,088.9ms | 2.1ms | 2.1ms |
| 初始化阶段长任务 | 1 个，约 3.07–3.09s | — | 0 | — |

优化后的批量状态合成中位数从 `3,081.3ms` 降至 `2.1ms`，约减少 `99.93%`。基线瓶颈不是坐标解析或 TypedArray hydration，而是对 SVG 连续执行 19,200 次分块 `drawImage`；优化版一次生成逻辑蒙版后进行分层合成，消除了该长任务。

页面检查确认进度为 `19,200 / 20,000`，坐标校验结果无重复、无越界，剩余池为 800。优化版 DOM 约 56 个节点、基线约 58 个节点，两者均只有一个可见 Canvas，未创建 20,000 个拼图 DOM。

## 单块点亮与取消

| 指标 | 基线中位数 | 基线 P95 | 优化中位数 | 优化 P95 |
| --- | ---: | ---: | ---: | ---: |
| 点击至绘制完成 | 1.35ms | 1.6ms | 1.1ms | 1.6ms |
| Canvas 增量绘制 | 0.5ms | 0.6ms | 0.1ms | 0.2ms |

10 次交替操作后进度回到 `19,200 / 20,000`，说明点亮和取消共用同一状态且没有重复计数。两种实现均满足中位数不超过 50ms、P95 不超过 100ms 的目标；优化版脏矩形更新开销更低。

## 500% 缩放与视觉检查

优化版从 100% 放大到 500% 的 8 次 Canvas 视口重绘耗时为 `1.9–2.8ms`，中位数约 `2.1ms`，观测期间没有长任务。500% 截图中未出现黑屏、黑影、残影或网格错位；网格边缘保持稳定，置灰层与彩色层位置一致。

与基线链路相比，优化版不会把固定分辨率 Canvas 纹理交给 CSS 放大，而是在每次变换后按当前视口重新绘制，因此避免了此前最明显的位图插值模糊。需要注意，SVG 作为 `Image` 解码后再进入 Canvas，最终仍是栅格输出，并不是“无限缩放”的矢量显示；清晰度上限由当前视口 backing store 与 DPR 决定。

本轮继续采集基线 500% 截图及 320/430px 自动截图时，本地浏览器策略阻止了预览地址的后续访问。未绕过该限制，因此这些项目没有伪造为已完成实测。基线的模糊结论来自其确定的固定 Canvas + CSS 放大链路及此前已复现的问题；响应式仍通过现有 rem、430px 封顶规则和构建进行静态检查，真机视觉验收仍需补充。

## 结论

- 19,200 个坐标的 Mock 生成、传输模拟和批量 hydration 都在毫秒级，不是初始化瓶颈。
- 基线逐块恢复造成约 3 秒主线程长任务，会表现为明显卡顿或页面短暂无响应。
- 优化版将初始化状态合成压缩至约 2ms，单块切换约 1ms，500% 重绘约 2ms；本轮未观察到明显延迟、黑影、残影或黑屏。
- 优化版通过视口级 Canvas 与 DPR 改善了 500% 清晰度，但仍需在低端 Android、iOS Safari 和高 DPR 真机上验证内存、SVG 解码及连续双指手势帧率。
- `requestAnimationFrame` 已合并高频变换，但按钮自动化不是连续触摸轨迹，本轮数据不能替代真实双指缩放的帧间隔测试。

## 后续验收建议

1. 在 320px、375px、430px 真机或可控浏览器中补齐截图，检查横向溢出和安全区域。
2. 在 DPR 2/3 的 iOS Safari 与中低端 Android 上连续执行 100% → 500% → 100% 双指缩放，采集至少 300 帧；目标 P95 帧间隔不超过 33ms。
3. 在 100% 与 500% 下分别点击四角、中心和网格边界，核对提交给后端的 `x`、`y`、`row`、`column` 与 `pieceIndex`。
4. 接入真实接口后，以服务端返回的 `isAcquired` 为准，并验证失败回滚、重复请求和并发点击。
5. 使用浏览器内存面板检查离屏 Canvas 峰值；按 `viewport × DPR` 和 DPR 上限 3 估算并设置移动端像素预算。
